Carefree ابزاری برای آفرینش با هوش مصنوعی است که کاملاً بهصورت محلی اجرا میشود. پروژهها، مواد، گفتوگوها و نتایج تولیدشده روی دستگاه خودتان ذخیره میشوند و هیچ دادهای درباره استفاده به هیچ سروری ارسال نمیشود. سرویس مدل را خودتان پیکربندی میکنید: هر رابط سازگار با OpenAI، ComfyUI محلی، و سرویس TTS محلی یا خودمیزبان.

## قابلیتها

| قابلیت | توضیح |
| --- | --- |
| بوم بینهایت | فیلمنامه، استوریبورد، شخصیتها، صحنهها و کلیپهای ویدیویی را در یک بوم سازمان دهید، با گروهبندی و اتصال. |
| آفرینش متنی | به هر رابط متنی سازگار با OpenAI متصل شوید و در گره متن فیلمنامه، تنظیمات شخصیت و توصیف نما را بنویسید. |
| تولید تصویر | با گردشکار ComfyUI خودمیزبان، نمای سهگانه شخصیت، صحنه و تصویر استوریبورد بسازید. |
| تولید ویدیو | با ComfyUI یا رابطهای رسانه طرف ثالث نمای ویدیویی بسازید، با پشتیبانی از مواد مرجع متعدد و امکان لغو تولید. |
| تولید صدا | به رابط `/audio/speech` سازگار با OpenAI متصل شوید؛ با استقرار محلی TTS، دوبله آفلاین ممکن است. |
| مدیریت مواد | تصویر، ویدیو و صدا همگی در یک کتابخانه مواد گرد میآیند، با پیشنمایش، سازماندهی و دانلود. |
| محلیبودن در اولویت | بهطور پیشفرض سرویس فقط روی ماشین محلی گوش میدهد؛ با فعالکردن اتصال دستگاهها در صورت نیاز میتوان در شبکه محلی به اشتراک گذاشت. |
| چندزبانه | رابط از ۲۱ زبان پشتیبانی میکند. |

مدلها، وضوح، مدت و تواناییهای صوتی موجود به ارائهدهنده و گردشکاری بستگی دارد که پیکربندی میکنید.

### جریان کاری معمول آفرینش

1. **فیلمنامه و استوریبورد**: با گره متن داستان، تنظیمات شخصیت و توصیف نما را سازمان دهید و با کمک مدل زبانی آن را بهبود ببخشید.
2. **شخصیتها و صحنهها**: تصویر مرجع وارد کنید، یا با گره تولید تصویر شخصیت، صحنه و تصویر استوریبورد بسازید.
3. **نماهای ویدیویی**: متن و تصویر مرجع را به هم وصل کنید، مدل ویدیو و روش تولید را انتخاب کنید و نما به نما بسازید.
4. **پیشنمایش و خروجی**: تصاویر و کلیپهای ویدیویی را در بوم پیشنمایش و سازماندهی کنید و مواد را برای ادامه پسازتولید دانلود کنید.

## نصب کلاینت

| سیستم | توضیح |
| --- | --- |
| Windows | بسته نصب را اجرا کنید؛ نصبکننده WebView2 را بهطور خودکار شناسایی و نصب میکند. اگر پس از نصب هنگام بازکردن برنامه از کار افتاد، [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) را دستی نصب کنید. |
| macOS (Apple Silicon) | Carefree را به «Applications» بکشید و مستقیم باز کنید. اگر پیام تأییدنشدن توسعهدهنده آمد، از «System Settings → Privacy & Security» اجازه بازکردن بدهید. |

پروتکل مورد استفاده `carefree://` است و برای راهاندازی مجدد و پیمایش پیوند عمیق در کلاینت به کار میرود.

## اجرا از سورس

به [Bun 1.4.3](https://bun.sh/docs/installation) نیاز دارد.

```sh
git clone <نشانی مخزن شما> carefree
cd carefree
bun install --frozen-lockfile

# حالت توسعه: Web و Server را با هم اجرا کنید
bun run dev
```

`http://127.0.0.1:3000` را باز کنید. در نخستین اجرا، گرهها، ابزارها و افزونههای داخلی مقداردهی اولیه میشوند و پوشه کاری `myProject` ساخته میشود.

### ساخت

```sh
# ساخت گرهها، افزونهها، Web و Server
bun run build

# ساخت خروجی مستقل Server
bun run build:server

# ساخت کلاینت دسکتاپ
bun run build:desktop
bun run package:desktop
```

نصبکننده Windows بهطور پیشفرض امضا نشده است. پیش از انتشار، متغیرهای محیطی زیر را تنظیم کنید تا `bun run build:desktop` / `bun run package:desktop` بهطور خودکار با `signtool` چهار لانچر (`startupLauncher.exe`، `protocolLauncher.exe`، `saveFileDialog.exe`، `updateHelper.exe`)، برنامههای کمکی نصبکننده (`checkWebView2.exe`، `checkRunning.exe`) و `Setup.exe` نهایی را امضا و تأیید کند:

| متغیر | توضیح |
| --- | --- |
| `CAREFREE_SIGN_PFX` | مسیر مطلق گواهی `.pfx`؛ در صورت تنظیمنشدن، امضا نادیده گرفته میشود |
| `CAREFREE_SIGN_PASSWORD` | رمز گواهی؛ اگر گواهی رمزنگاری نشده باشد خالی بگذارید |
| `CAREFREE_SIGN_TIMESTAMP_URL` | سرویس مهر زمانی RFC3161، بهطور پیشفرض `http://timestamp.digicert.com` |
| `SIGNTOOL_PATH` | مسیر `signtool.exe`، بهطور پیشفرض بهطور خودکار در Windows SDK جستوجو میشود |

به محیط Windows x64 و Windows SDK نیاز دارد. برنامه اصلی اپلیکیشن داخل tar بهروزرسانی افزایشی است و در دامنه این امضا نیست؛ اگر امضا لازم است، ابتدا فایل اپلیکیشن را امضا کنید و سپس tar و فهرست بهروزرسانی را دوباره بسازید.

در GitHub Actions از Secrets مخزن برای تأمین گواهی استفاده کنید؛ پس از پیکربندی، ساخت Windows بهطور خودکار امضا و تأیید میشود:

| Secret | توضیح |
| --- | --- |
| `CAREFREE_SIGN_PFX_BASE64` | متن Base64 فایل گواهی `.pfx`؛ اگر پیکربندی نشده باشد CI از امضا صرفنظر میکند |
| `CAREFREE_SIGN_PASSWORD` | رمز خروجی PFX؛ اگر رمزنگاری نشده باشد خالی بگذارید |

گواهی فقط در مرحله ساخت موقتاً روی دیسک ذخیره میشود و پس از پایان کار پاک میشود. نشانی مهر زمانی را میتوان با متغیر محیطی `CAREFREE_SIGN_TIMESTAMP_URL` تغییر داد.

### سرور

```sh
bun run build:server
mkdir -p data/workspaces/myProject
bun run start:server
```

- بهطور پیشفرض روی `127.0.0.1:3000` گوش میدهد و به شبکه بیرونی باز نیست.
- پورت را میتوان با `TOONFLOW_SERVER_PORT` تغییر داد.
- اگر واقعاً به دسترسی در شبکه محلی نیاز دارید، `TOONFLOW_SERVER_HOST=0.0.0.0` را تنظیم کنید و خودتان با فایروال مبدأ را محدود کنید؛ بهتر است «اتصال دستگاهها» را در برنامه فعال کنید که فقط در صورت نیاز روی پورت جداگانه گوش میدهد.
- پیکربندی، افزونهها و فضای کاری بهطور پیشفرض در `data/` ذخیره میشوند. در استفاده راه دور میتوان با تونل SSH به آن دسترسی داشت:

```sh
ssh -N -L 3000:127.0.0.1:3000 user@server-address
```

## پیکربندی مدلها

«Model service» را در تنظیمات باز کنید:

- **مدل متنی**: یک ارائهدهنده سازگار با OpenAI اضافه کنید و نشانی رابط، API Key و فهرست مدلها را وارد کنید.
- **تصویر / ویدیو**: ارائهدهنده ComfyUI را نصب و پیکربندی کنید و نشانی ComfyUI محلی و گردشکار را وارد کنید.
- **صدا**: ارائهدهنده TTS محلی را نصب کنید، نشانی پیشفرض `http://127.0.0.1:8880/v1` است و میتوان آن را به هر سرویس سازگار با `/audio/speech` اشاره داد.
- **ارائهدهنده سفارشی**: میتوان در تنظیمات فایل آداپتور `.ts` را وارد کرد و هر رابط طرف ثالث را گسترش داد.

API Key فقط در پوشه داده محلی ذخیره میشود و بارگذاری نمیشود.

## Docker

مخزن [Dockerfile](../../Dockerfile)، [Compose configuration](../../compose.yaml) و [build exclusion rules](../../.dockerignore) را فراهم میکند؛ ایمیج بر پایه Bun 1.4.3 است و FFmpeg در آن گنجانده شده.

```sh
docker compose up -d --build
```

- به `http://127.0.0.1:3000` دسترسی داشته باشید.
- دادهها در حجم نامدار `toonflowData` ذخیره میشوند (در داخل کانتینر روی `/app/data/` سوار شده)؛ توقف یا بازسازی کانتینر دادهها را از بین نمیبرد، از `docker compose down -v` استفاده نکنید.
- سرویس داخل کانتینر روی `0.0.0.0` گوش میدهد؛ مبدأ دسترسی را با نگاشت پورت یا پروکسی معکوس کنترل کنید.

دستورهای رایج:

```sh
docker compose logs -f toonflow
docker compose stop
docker compose start
docker compose down
```

## داده و حریم خصوصی

- برنامه هیچ آمار ناشناس یا داده تلهسنجی جمعآوری یا ارسال نمیکند.
- پروژهها، دستورها، گفتوگوها و محتوای تولیدشده در پوشه داده محلی ذخیره میشوند.
- فقط پس از پیکربندی ارائهدهنده مدل، درخواستها به رابط مربوط ارسال میشود؛ محتوای درخواست تابع شرایط خدمات همان ارائهدهنده است.
- بهروزرسانی خودکار بهطور پیشفرض خاموش است و میتوان در تنظیمات منبع بهروزرسانی خودمیزبان را پیکربندی کرد.
