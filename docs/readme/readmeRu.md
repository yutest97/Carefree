Carefree — полностью локальный инструмент для AI-творчества. Проекты, материалы, диалоги и результаты генерации хранятся на вашем устройстве, а данные об использовании не отправляются ни на один сервер. Модельные сервисы вы настраиваете сами: любой OpenAI-совместимый интерфейс, локальный ComfyUI и локальный или собственный TTS-сервис.

## Возможности

| Возможность | Описание |
| --- | --- |
| Бесконечный холст | Организуйте сценарий, раскадровку, персонажей, локации и видеоролики на одном холсте с помощью группировки и связей. |
| Работа с текстом | Подключите любой OpenAI-совместимый текстовый интерфейс и пишите сценарии, описания персонажей и кадров в текстовых узлах. |
| Генерация изображений | Создавайте листы с тремя видами персонажей, локации и кадры раскадровки через собственные рабочие процессы ComfyUI. |
| Генерация видео | Генерируйте видеокадры через ComfyUI или сторонние медиаинтерфейсы; поддерживаются несколько референсов и отмена генерации. |
| Генерация речи | Подключитесь к OpenAI-совместимому интерфейсу `/audio/speech`; локально развёрнутый TTS обеспечивает озвучку офлайн. |
| Управление материалами | Изображения, видео и аудио попадают в библиотеку материалов, где их можно просматривать, упорядочивать и скачивать. |
| Локальность | По умолчанию сервис слушает только на этом устройстве; при необходимости включите обмен между устройствами для работы в локальной сети. |
| Многоязычность | Интерфейс поддерживает 21 язык. |

Доступные модели, разрешения, длительность и возможности работы с аудио зависят от настроенных вами провайдеров и рабочих процессов.

### Типичный процесс создания

1. **Сценарий и раскадровка**: в текстовых узлах соберите историю, описания персонажей и кадров, итеративно дорабатывая их с помощью языковой модели.
2. **Персонажи и локации**: импортируйте референсы или создавайте персонажей, локации и кадры раскадровки в узлах генерации изображений.
3. **Видеокадры**: подключите текстовые и графические референсы, выберите видеомодель и режим генерации, затем генерируйте кадр за кадром.
4. **Просмотр и экспорт**: просматривайте и упорядочивайте изображения и видеоролики на холсте, скачивайте материалы для дальнейшего монтажа.

## Установка клиента

| Система | Описание |
| --- | --- |
| Windows | Запустите установщик: он сам обнаружит и установит WebView2. Если после установки приложение закрывается при запуске, установите [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) вручную. |
| macOS (Apple Silicon) | Перетащите Carefree в «Программы» и откройте. Если macOS сообщает, что разработчика не удаётся подтвердить, разрешите запуск в «Системные настройки → Конфиденциальность и безопасность». |

Протокол `carefree://` используется для перезапуска и перехода по глубоким ссылкам внутри клиента.

## Запуск из исходного кода

Требуется [Bun 1.4.3](https://bun.sh/docs/installation).

```sh
git clone <адрес-вашего-репозитория> carefree
cd carefree
bun install --frozen-lockfile

# Режим разработки: одновременно запускаются Web и Server
bun run dev
```

Откройте `http://127.0.0.1:3000`. При первом запуске инициализируются встроенные узлы, инструменты и плагины, а также создаётся рабочий каталог `myProject`.

### Сборка

```sh
# Сборка узлов, расширений, Web и Server
bun run build

# Сборка отдельного Server-артефакта
bun run build:server

# Сборка настольного клиента
bun run build:desktop
bun run package:desktop
```

Установочные пакеты Windows по умолчанию не подписываются. Задайте следующие переменные окружения перед публикацией, и `bun run build:desktop` / `bun run package:desktop` автоматически подпишут и проверят подпись четырёх лаунчеров (`startupLauncher.exe`, `protocolLauncher.exe`, `saveFileDialog.exe`, `updateHelper.exe`), вспомогательных программ установщика (`checkWebView2.exe`, `checkRunning.exe`) и итогового `Setup.exe` с помощью `signtool`:

| Переменная | Описание |
| --- | --- |
| `CAREFREE_SIGN_PFX` | Абсолютный путь к сертификату `.pfx`; если не задан, подпись пропускается |
| `CAREFREE_SIGN_PASSWORD` | Пароль сертификата; оставьте пустым, если сертификат не зашифрован |
| `CAREFREE_SIGN_TIMESTAMP_URL` | Служба меток времени RFC3161, по умолчанию `http://timestamp.digicert.com` |
| `SIGNTOOL_PATH` | Путь к `signtool.exe`; по умолчанию ищется автоматически в Windows SDK |

Требуются Windows x64 и Windows SDK. Основная программа приложения находится внутри tar-архива инкрементального обновления и не входит в эту подпись; если её нужно подписать, сначала подпишите файл приложения, а затем заново создайте tar и манифест обновления.

В GitHub Actions сертификат передаётся через Secrets репозитория; после настройки сборки Windows автоматически подписываются и проверяются:

| Secret | Описание |
| --- | --- |
| `CAREFREE_SIGN_PFX_BASE64` | Текст сертификата `.pfx` в кодировке Base64; если не настроен, CI пропускает подпись |
| `CAREFREE_SIGN_PASSWORD` | Пароль экспорта PFX; оставьте пустым, если он не задан |

Сертификат записывается на диск только на время шага сборки и удаляется по завершении задания. Адрес службы меток времени можно переопределить переменной окружения `CAREFREE_SIGN_TIMESTAMP_URL`.

### Сервер

```sh
bun run build:server
mkdir -p data/workspaces/myProject
bun run start:server
```

- По умолчанию слушает `127.0.0.1:3000` и не доступен из интернета.
- Порт можно изменить с помощью `TOONFLOW_SERVER_PORT`.
- Если доступ из локальной сети действительно нужен, задайте `TOONFLOW_SERVER_HOST=0.0.0.0` и ограничьте источники с помощью межсетевого экрана; вместо этого рекомендуется включить в приложении «Связь устройств» — она слушает отдельный порт только при необходимости.
- Конфигурация, плагины и рабочие области по умолчанию хранятся в `data/`. Для удалённого использования подключайтесь через SSH-туннель:

```sh
ssh -N -L 3000:127.0.0.1:3000 пользователь@адрес-сервера
```

## Настройка моделей

Откройте «Сервисы моделей» в настройках:

- **Текстовые модели**: добавьте OpenAI-совместимого провайдера, укажите адрес интерфейса, API Key и список моделей.
- **Изображения / видео**: установите и настройте провайдера ComfyUI, указав адрес локального ComfyUI и рабочие процессы.
- **Речь**: установите локального провайдера TTS; адрес по умолчанию — `http://127.0.0.1:8880/v1`, также можно указать любой сервис, совместимый с `/audio/speech`.
- **Собственные провайдеры**: в настройках можно импортировать файлы адаптеров `.ts`, чтобы подключить любой сторонний интерфейс.

API Key хранятся только в локальном каталоге данных и не передаются вовне.

## Docker

Репозиторий содержит [Dockerfile](../../Dockerfile), [конфигурацию Compose](../../compose.yaml) и [правила исключения при сборке](../../.dockerignore). Образ основан на Bun 1.4.3 и включает FFmpeg.

```sh
docker compose up -d --build
```

- Доступ: `http://127.0.0.1:3000`.
- Данные хранятся в именованном томе `toonflowData` (монтируется в `/app/data/` внутри контейнера); остановка или пересоздание контейнера не приводит к потере данных, поэтому не используйте `docker compose down -v`.
- Сервис внутри контейнера слушает `0.0.0.0`; ограничьте источники доступа с помощью проброса портов или обратного прокси.

Частые команды:

```sh
docker compose logs -f toonflow
docker compose stop
docker compose start
docker compose down
```

## Данные и конфиденциальность

- Приложение не собирает и не отправляет анонимную статистику или телеметрию.
- Проекты, промпты, диалоги и сгенерированный контент хранятся в локальном каталоге данных.
- Запросы отправляются на соответствующий интерфейс только после настройки провайдера модели; содержимое запросов регулируется условиями обслуживания этого провайдера.
- Автоматическое обновление по умолчанию отключено; собственный источник обновлений можно настроить в параметрах.
